## 3. Package Management

**File:** `src/pages/admin/AdminPackages.tsx`
**Permission:** `packages`

### Purpose

Full CRUD management for Hajj/Umrah travel packages including pricing, accommodations, dates, galleries, and capacity tracking.

### Features

- **Package list** with search and status filter (`active`, `draft`, `archived`)
- **Create/Edit modal** with multi-section form:
  - Basic info: name, type (hajj/umrah), category (economy/standard/premium/vip), price, currency
  - Capacity: total slots, available slots
  - Dates: multiple outbound/return date pairs with airline info (`package_dates` table)
  - Accommodations: Makkah/Madinah hotel details with star ratings (`package_accommodations`)
  - Gallery: image uploads to Supabase Storage
  - Departure cities: multi-select array
  - Features: rich text or list of included amenities
  - Agent discount: percentage for wholesale pricing
- **Status toggle** — activate/archive packages
- **Capacity bar** — visual progress of booked vs. available slots

### Database Tables

- `packages` — Core package data
- `package_dates` — Travel date ranges per package
- `package_accommodations` — Hotel info per package
- `package_gallery` — Image URLs per package

## 4. Payment Management

**File:** `src/pages/admin/AdminPayments.tsx`
**Permission:** `payments`

### Purpose

Review, verify, and manage all payment transactions across the platform. Central hub for financial reconciliation.

### Features

- **Payment table** with columns: Pilgrim, Amount, Method, Status, Date, Receipt
- **Status filters:** `pending`, `verified`, `rejected`, `all`
- **Manual verification:** Admin marks bank transfers as verified with `verified_by` and `verified_at` timestamps
- **Receipt view:** Uploaded proof-of-payment images from pilgrims
- **Bulk actions:** Export to CSV

### Payment Methods Supported

| Method            | Flow                                                   |
| ----------------- | ------------------------------------------------------ |
| `bank_transfer` | Pilgrim uploads receipt → Admin verifies manually     |
| `cash`          | Admin creates via Direct Registration → auto-verified |
| `paystack`      | Online payment → webhook auto-verifies                |

### Verification Workflow

```
Payment created (status: pending)
  → Admin reviews receipt image
  → Admin clicks "Verify" → updates: status='verified', verified_by=admin_id, verified_at=now()
  → Booking auto-updates to 'confirmed' if payment covers full amount
```

## 10. Agent Applications

**File:** `src/pages/admin/AdminAgentApplications.tsx` (1000 lines)
**Permission:** `agents`

### Purpose

Review partnership applications and directly create agent accounts. The complete agent lifecycle management hub.

### Tabs

| Tab           | Content                           |
| ------------- | --------------------------------- |
| Pending       | Applications awaiting review      |
| Applications  | All approved applications history |
| Active Agents | Verified agents with full CRUD    |
| Rejected      | Declined applications             |
| Logs          | Complete application history      |

### Workflows

#### Application Approval Flow

```
Agent submits application (public form)
  → Row created in agent_applications (status: pending)
  → Admin reviews → clicks "Approve"
  → ApproveDialog opens: set temp password + commission rate/type
  → Edge Function: approve-agent-application
    → Creates auth user, profile, agent record
    → Returns agent_code
  → Agent receives credentials → logs in → changes password
```

#### Direct Agent Creation (no application)

```
Admin clicks "Create Agent"
  → CreateAgentDialog: full_name, business_name, email, phone, temp_password, commission
  → Edge Function: create-agent-direct
    → Creates auth user + profile + agent record
  → Success dialog shows credentials to copy/share
```

#### Edit Agent

- Modify: business_name, contact_person, email, phone, commission_rate, commission_type, status
- Commission type toggle: "% Rate" vs "₦ Fixed"
- Warning shown if percentage > 100% (likely meant to be fixed)

#### Delete Agent

- Removes agent record only (does NOT delete auth user)

### Stat Cards (4)

- Pending count, Approved count, Rejected count, Total applications

## Cross-Cutting Patterns

### State Management

- **TanStack Query** for all server state (queries + mutations)
- **Cache invalidation** on mutations via `queryClient.invalidateQueries()`
- **Optimistic updates** where applicable (e.g., status toggles)

### Realtime Subscriptions

- Team Chat: `postgres_changes` on `staff_messages`
- Support Tickets: `postgres_changes` on support message tables

### Export Utilities

- **CSV export:** `downloadCSV()` from `AdminPilgrimDetailDialog`
- **PDF generation:** `jsPDF` + `html2canvas` for ID tags
- **Bulk document download:** `downloadMultipleDocuments()` → ZIP file
- **Print view:** Dynamic HTML in new window with `window.print()`

### Design System Tokens

All admin pages use the Royal Indigo design system:

- `admin-section-title` class for page headings
- `admin-card` class for card containers
- `glass-panel-light` for data tables
- `gold-gradient` for primary CTA buttons
- `shadow-gold` / `shadow-gold-lg` for button shadows

### Adding a New Admin Module

1. Create page component in `src/pages/admin/`
2. Add route in router config
3. Add entry to `ALL_MENU_ITEMS` in `AdminSidebar.tsx` with unique permission key
4. Register permission key in Staff Management module
5. Update this documentation file
