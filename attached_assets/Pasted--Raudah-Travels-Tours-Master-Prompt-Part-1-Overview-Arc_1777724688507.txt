## 1. What Is This App?

**Raudah Travels & Tours** is a full-stack **Hajj & Umrah travel booking platform** built for the Nigerian market. It serves three user types through dedicated dashboards:

| Role                     | Portal           | Base Route     |
| ------------------------ | ---------------- | -------------- |
| **Pilgrim (User)** | User Dashboard   | `/dashboard` |
| **Travel Agent**   | Agent B2B Portal | `/agent`     |
| **Admin / Staff**  | Admin Console    | `/admin`     |

Additionally there is a **public-facing landing page** at `/` with SEO-optimised marketing content, package browsing, and a "Become an Agent" application flow.

## 4. Authentication & Authorization

### Role Hierarchy

```
super_admin → admin → moderator → staff → agent → user
```

- **`super_admin`** and **`admin`**: Full access to all admin features and permissions.
- **`staff`**: Access only to admin pages where they have explicit `staff_permissions` entries.
- **`agent`**: Access to the Agent B2B portal only.
- **`user`**: Access to the User Dashboard only.

### How It Works

1. **Registration:** User signs up → Supabase Auth trigger creates a `profiles` row and a `user_roles` row with role `'user'`.
2. **Login:** `AuthContext.signIn()` fetches `profiles`, `user_roles`, and `staff_permissions` in parallel, then redirects based on highest role.
3. **Route Protection:** `<ProtectedRoute requiredRole="staff">` checks `hasRole()` (hierarchical). `<ProtectedRoute requiredPermission="payments">` checks `hasPermission()`.
4. **Database RLS:** Every table has Row Level Security. The `has_role()` and `has_permission()` SQL functions mirror the frontend logic server-side.

### Staff Permissions (Granular)

```
overview, packages, payments, pilgrims, analytics, id_tags,
visa_management, agents, bank_accounts, activity, amendments,
support, settings, staff_management
```
